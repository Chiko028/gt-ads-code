# ADR-0001: Modularer Monolith statt Microservices

Status: Vorgeschlagen – wartet auf Freigabe durch den Betreiber
Datum: 2026-11-09
Quelle: ARCHITEKTUR §1, §14 (ADR-01)

## Kontext
Ein Betreiber, begrenzte Ressourcen (6 vCPU, ~11,7 GiB RAM), später mögliche Aufteilung.

## Entscheidung
Ein Backend-Prozess (`api`) plus Worker, klar getrennte Module (siehe PROJEKTSTRUKTUR §3), Schnittstellen nur über definierte Aufrufe.

## Alternativen
Microservices (mehr RAM/Betrieb), reiner Monolith ohne Modulgrenzen (schwer teilbar).

## Folgen
Weniger Betriebsaufwand; Modulgrenzen müssen per Review/Tests durchgesetzt werden.

## Änderungen
Nur per neuem ADR (Status „Ersetzt durch ADR-nnnn"); Betreiberfreigabe erforderlich.
